# P10 — Owners are members, and member messages arrive — work list

Owner decisions, 2026-10-12 ([team-flow](team-flow.md) decisions 11 and 14):

- Every person is a member. Owner authority is a role a member holds, and several members may
  hold it.
- The room decides where a record belongs. A person works on personal records in its own DM and
  on common records in the common channel (the group room).
- Delta processing and other unattended work run in the common session, not as a person.
- Each member, owners included, gets the reports it asks for in its own channel, and its own cron
  jobs, heartbeat checks and event notices; each person has its own skills (2026-10-12, evening).
- An owner can suspend and resume another owner; no owner suspends itself, and no owner is
  offboarded.
- An owner's DM session is a member's session: the member prompt, native boundary and tools, no
  web tools. It reads the owner rules read-only (added after its first live answer broke a rule).
- The owner's DM chat from before P10 moves to the owner's personal records.

Evidence: [checks](../checks.md#p10-plan-pass-2026-10-12) (plan pass and the Opus review).

## The model

Core's one active `kind = 'owner'` principal stays, and becomes the common principal: no person,
no Telegram identity. It runs the common session (`owner:runtime`, `owner:replay`), issues grants
and is never suspended. Every person is a `kind = 'member'` principal. Owner authority is a role
on a member, kept in the registry.

This keeps core's contracts: one active owner principal (`m/064`), grants issued by the active
owner principal, transitions, export and erasure for members only, and the session that is never
removed (`principal-sessions.ts:133`). `moveIdentityToMember` already moves an owner-bound
identity to a new member principal. A role cannot be a grant: grants hold only sources and
memory scopes (`m/065`), and a member memory grant may not overlap the owner's default scopes
(`principal-access.ts:8-20`).

| Room                                                           | Session                                          | Reads                                                                                                                  | Unscoped writes bind |
| -------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | -------------------- |
| A person's DM                                                  | That person's member session, workspace and chat | Its personal records; with the `owner` role, the common records through MAMA actions; otherwise its granted partitions | `user:<person>`      |
| The common channel (`owner_chat_id`)                           | The common session; the sender is recorded       | Common records; nobody's personal records, because the whole room reads the answer                                     | Common scopes        |
| Unattended (deltas, record orders, replay, common report jobs) | The common session                               | Common records                                                                                                         | Common scopes        |

In a DM, an owner reads the common records but changes them only in the common channel: common
work, owner policy and rules, the time zone, `report.publish` and the wiki. `drive.download` in a
DM saves into that person's own downloads, so it is a read there (a live DM could not open a Drive
sheet, 2026-10-15). A
correction to common work said in a DM stays personal; it reaches deltas and reports when it is
said in the common channel or shared (P10.3). Notices, alerts, files and the full report keep
going to `owner_chat_id`, the common channel, until P10.4 (`telegram.ts:293-297`; the config's
`os_report_chat_id` has no reader).
