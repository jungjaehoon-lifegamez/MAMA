## The 1.0 gate

1.0 ships when all four hold.

- **G1 Fresh install.** On a clean macOS user account and a clean Ubuntu 24.04 LTS host, a person who has not used MAMA follows only the
  docs from nothing to: a DM reply, one connected source recorded as work, an evidence-backed answer
  to "who is working on what", and the next scheduled report. Each run records its steps, its time
  and every place the person had to leave the docs. The runs never touch this machine's live
  `~/.mama` or `~/.claude/mama-memory.db`. The Linux run uses the most common setup, not
  the Steam Deck (owner, 2026-11-14, replacing 2026-10-15): Ubuntu 24.04 LTS on x86-64 with a
  systemd user service and linger. The test
  host is the owner's WSL2 Ubuntu 24.04; any x86-64 Ubuntu 24.04 VM or server replaces it if that
  is not available. WSL2 is only the test host: Windows stays out of 1.0, and the host's own
  behaviour (Windows PATH, the VM stopping when idle, the browser) goes in the run's notes.
- **G2 Upgrade.** An install of the release before 1.0, with records, sessions and settings in it,
  upgrades to 1.0 by the documented command and keeps them. Every 1.x release passes the same check.
- **G3 Owner flow.** C1–C5 ([plan](../plan.md#owner-checks)) are accepted by the owner on live data.
  The daily self-check (#502) runs every day, reads the day and publishes its page; the owner
  accepts a stretch of those pages. Accepted 2026-11-16 on live operation: a page on every day of
  October and 1–15 November.
- **G4 Nothing unverified is offered.** Every messenger, source and feature that `mama init` or the
  docs offer has run live on a fresh install, or both label it experimental.

`~/.mama` stays a disposable testbed on the development machine (AGENTS.md). A 1.0 user's data is
not disposable: from 1.0 an upgrade keeps it (G2, R4, R5).

## Not in 1.0

- Windows (owner, 2026-10-15).
- Docker (owner, 2026-11-16). A Linux install serves the same hosts with the required shell sandbox
  intact. In a container on stock Ubuntu 24.04 the sandbox (bwrap) starts only with seccomp,
  AppArmor, Docker's `/proc` masking and the host's user-namespace restriction all lifted, close to
  a privileged container; on WSL2, which has no AppArmor, a seccomp profile was enough
  (checks "Docker out of 1.0"; the image, compose file and container mode are in the closed PR
  #572).
- API keys and local models: MAMA signs in through the Claude and Codex CLIs.
- A browser admin panel: administration stays an interactive owner request in chat (AGENTS.md).
- A translated viewer, mobile and desktop apps, a skills marketplace, importers from other agents.
