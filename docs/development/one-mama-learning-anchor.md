# 원마마 개선 앵커: 경험이 다음 행동을 바꾼다

2026-09-08 오너와 재확인. INTENT v6의 실행·평가 기준이며, 새 인텐트나 완료 선언이 아니다.

## 목표

관련 상황 → 작은 힌트 → 자료의 점진 조사 → 에이전트의 판단·수행 → 실제 결과 관측
→ 근거 있는 교정 → 다음 관련 상황에서 개선된 행동.

모델이 오류 후 호출 방식을 바꿔 성공한 사실은 같은 실행 안의 문제 해결 능력을 보여준다.
그 능력이 재시작·담당 교체 뒤에도 이어질 수 있다는 것은 검증할 가설이다. 실패를 먼저
모델 지능 부족으로 돌리지 않는다. 정답 서식이나 실행 순서를 개발자가 대신 작성해서
성공한 결과를 자기교정 성공으로 세지 않는다.

## 책임

- 에이전트: 힌트의 관련성 판단, 원문 조사, 수행 방법 선택, 결과 해석, 경험의 유지·수정·폐기.
- 호스트: 신원·공유 범위, 원문과 실행 근거의 지속성, 점진 조회, 일관된 도구 계약, 버전·중복 효과·복구.
- 힌트: 왜 관련 있을 수 있는지, 적용/비적용 조건, 어떤 경험·근거를 더 볼 수 있는지.
  긴 매뉴얼이나 강제 행동 순서가 아니다. 사용하지 않는 판단도 가능하다.
- 진화: 같은 경험의 원문·이력·조건을 보존하며 갱신한다. 실패 횟수로 규칙을 자동 변경하거나
  모델이 말한 성공을 검증된 성공으로 승격하지 않는다. 도구나 환경이 달라지면 재검토한다.

## 재평가

0.52.0-local.1의 scope/revision/CAS/projection 복구와 공통 owner 권한은 재사용한다.
하지만 기존 policy/lesson 작성자, 운영 브리프, 설치 스킬, trigger 절차가 별도 행동 기준으로
병행된다. 특히 예약 실행은 교훈 저장 대신 최종 메시지에 적으라는 지시를 여전히 포함한다.
실제 후보는 저장 기반이며 자기교정 순환의 완료 버전이 아니다.

모든 내용을 한 파일로 합치거나 한 호스트 판단기로 옮기는 것은 목표가 아니다.
동일한 업무·경험·근거에 접근하는 길과 현재 유효한 버전을 일관되게 하고,
행동의 의미와 적용 여부는 에이전트에 돌려준다.

## 검증 범위

Code-Act는 첫 사례이며 전체 범위가 아니다. 스킬이 발견되지 않거나 무관한 스킬이 주입되는 경우,
보드가 같은 근거로 불필요하게 재개정되는 경우도 필수 사례다. 요청·스킬 선택·조사·판단·수행·
결과 반영 전체에서 실패와 성공을 연결한다. 정당한 재조사나 실제 상태 변경은 반복 오류로 세지 않는다.

## 필수 증거

1. Code-Act 실패와 성공의 차이를 에이전트가 조사하여 경험으로 만들고, 새 실행의 다른 요청에서
   같은 오류를 반복하지 않으면서 실제 일을 완료한다. 없는 도구, 잘못된 인자, 권한 거절,
   일시 장애를 구분한다. 기능이 없는데 사용했다고 주장하는 것은 실패다.
2. 오너가 보고만 교정했을 때 상충 지침을 실제 대체하고 다음 보고를 개선한다.
   일반 대화와 다른 업무로 규칙을 잘못 확대하지 않는다.
3. 별도 학습 지시 없이 실제 비보고 작업 결과로 경험을 교정하고, 처음 보는 파일의
   원본 보존·새 산출물·근거 충실도를 개선한다. 관측이 부족하면 미입증이다.
4. 동일 모델·추론 강도·도구 권한·동결 자료에서 기존 긴 지시와 작은 힌트 조건을 비교한다.
   사실성·완료 품질·교정 전이와 시간·모델 왕복·캐시 포함 사용량을 함께 기록한다.
5. 실제 로컬 운영에서 반복 사용한다. 재시작과 다른 지원 모델의 전이를 구분해 증명한다.

I-01/I-02/I-06/I-07, TG-03/TG-04/TG-05/TG-06 및 기존 v1 Case·파일·팀 목적을 유지한다.
