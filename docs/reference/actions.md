# Owner actions

Use these actions inside a MAMA OS owner turn to read evidence, maintain work, and publish results.
The public development-memory MCP server has a [separate tool surface](mcp-tools.md).

This table lists the owner grants of the runtime assembly (`OWNER_ACTIONS`): 48 actions. `judge`
needs Jev enabled, `manage.member.enroll` Telegram and `member_root`, `deliver.<messenger>.file` an
enabled messenger with `file_delivery` on, and `deliver.drive.file` a `delivery.drive` folder.
Purpose text is the first sentence of each registered summary; inputs come from its schema. Required
markers describe top-level schema requirements; conditional requirements still apply. A turn starts
with an index only: each action's name and first sentence. The agent reads an action's arguments
with `help({actions: [name]})` before it first calls it, and a procedure (full report, recording,
corrections, sources, files, wiki) with `help({topic})` when a turn needs one.

Read source hits with `source.read` using `observationRef` or `observationRefs`; each reference
identifies its own source. Continue bounded reads with the returned cursor or
offset. Wiki section replacements use versions returned by a prior read; work revisions can omit
the current revision for a single-owner append and return the new revision number. File delivery accepts an
absolute path under the workspace files directory: `deliver.<messenger>.file` sends it to that
messenger's owner chat, and `deliver.drive.file` uploads it to the owner's Drive delivery folder.

The core catalog also registers actions that the owner runtime does not expose. In particular,
`graph.node.put`, `memory.update`, `memory.checkpoint.load` and `source.ingest` are not owner tools.
A name present in the shared catalog is not sufficient to make it callable by this agent.
